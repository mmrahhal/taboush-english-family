# طبوش V5 — بوابتان للطالب وولي الأمر

## 1) قبل البدء
هذه حزمة جديدة لمستودع GitHub Pages الحالي `taboush-english-family`، وتستخدم مشروع Firebase `taboush-family` الموجود بالفعل. احتفظ بنسخة من الإصدار السابق قبل استبداله. **لا تنشر V5 قبل نشر قواعد Firestore الجديدة**، ولا تضع بريد الطلاب أو كلمات المرور في ملفات GitHub.

## 2) ملف cloud-config.js
انسخ من Firebase Console → Project Settings → Your Apps → SDK setup (Config): `apiKey`, `authDomain`, `projectId`, `appId`.

افتح Firebase → Authentication → Users، وانسخ **UID الكامل لحساب ولي الأمر** (ليس البريد)، ثم استبدل `PASTE_PARENT_UID` داخل `cloud-config.js`.

**مهم:** ضع القيمة نفسها بدل `PASTE_PARENT_UID` في موضعَيها داخل `firestore.rules`. لن تنجح عملية الربط قبل ذلك. لا تغير UID عند كل تسجيل دخول.

## 3) تحديث قواعد Firestore (قبل رفع ملفات الموقع)
Firebase Console → Firestore Database → Rules: استبدل القواعد الحالية بمحتوى `firestore.rules` بعد إدخال UID، ثم اضغط Publish. القواعد تمنع الطلاب من تعديل الملاحظات والمكافآت ومن رؤية بيانات طلاب آخرين. تحقق من صلاحية ولي الأمر والطالب في Rules Playground أو Emulator قبل استخدام البيانات الحقيقية.

## 4) إنشاء حساب الطالب
- حساب ولي الأمر الحالي يظل كما هو ولا حاجة لإنشائه ثانية.
- افتح المنصة الجديدة، اختر **تسجيل الطالب**.
- اكتب بريدًا خاصًا بالطالب أو بريدًا تديره الأسرة **بموافقة ولي الأمر** مع كلمة مرور منفصلة. لا تستخدم البريد نفسه المستخدم لحساب ولي الأمر.
- اضغط إنشاء حساب طالب. سيظهر UID الطالب في شاشة انتظار الربط.
- يمكن أيضًا إنشاء حساب الطالب من Firebase Authentication → Users → Add user ثم تسجيل دخوله من بوابة الطالب، ونسخ UID.
- **ملاحظة:** تفعيل التسجيل بالبريد في Firebase يتيح نظريًا لأي شخص إنشاء حساب Auth، لكن قواعد Firestore تمنع وصول الحساب غير المرتبط إلى بيانات الأسرة. إذا كان المطلوب منع إنشاء أي حساب خارجي تمامًا، يجب بناء خدمة خلفية مقيّدة لإنشاء المستخدمين أو استخدام Identity Platform؛ هذه النسخة لا توفر المنع من إنشاء Auth بذاته.

## 5) ربط الطالب بولي الأمر
- افتح نافذة خاصة أو جهازًا آخر لحساب ولي الأمر ثم اختر **دخول ولي الأمر**.
- الصق UID الطالب، واكتب اسمه، واختر المستوى، ثم **اعتماد الربط**.
- يعود الطالب ويضغط **التحقق من قبول الربط** (أو يحدّث الصفحة) فتظهر دروسه المستقلة.

## 6) التعلم والمتابعة
- الطالب: 24 درسًا مستوردة من محتوى طبوش السابق، وأسئلة مع نطق آلي ونقاط XP وشارات حسب النقاط.
- ولي الأمر: عرض إحصاءات كل طالب، كتابة ملاحظات، وإنشاء مكافآت مرتبطة بالنقاط.
- الطالب: يرى الرسائل والمكافآت التي أضافها ولي أمره.
- انتبه: أرقام XP تحفيزية ويمكن العبث بها تقنيًا في تطبيق يعتمد على المتصفح؛ إذا أردت مكافآت مالية أو جوائز مهمة، يجب التحقق من الإنجازات على خادم موثوق.

## 7) النشر في GitHub
- أنشئ نسخة احتياطية من ملفات المستودع الحالية، وخاصة `index.html`, `cloud.js`, `cloud-config.js` و`firestore.rules`.
- ارفع الملفات الجديدة التالية إلى **جذر** فرع `main`، واستبدل `index.html` و`cloud-config.js` و`firestore.rules` السابقة:
  `index.html`, `app.js`, `lessons.json`, `cloud-config.js`, `firestore.rules`, `README_AR.md`, `.nojekyll`.
- **احذف `cloud.js` القديم** بعد أخذ نسخة احتياطية منه، لأنه غير مستخدم في V5.
- راجع أحدث نشر في GitHub Actions ثم افتح الرابط الصحيح (انتبه لاختلاف أسماء المستخدمين المتشابهة).
- لا حاجة إلى npm أو Vite.

## 8) اختبار آمن
1. أنشئ حساب طالب تجريبي بالبريد وكلمة المرور.
2. تأكد أن الحساب الجديد لا يستطيع الاطلاع على دروس الأسرة قبل الربط.
3. اربطه عبر UID من لوحة ولي الأمر.
4. سجّل الدخول كطالب وأجب عن سؤال؛ يجب أن تزيد XP.
5. من لوحة ولي الأمر افتح تقريره وأرسل رسالة «أحسنت».
6. افتح قسم الرسائل من حساب الطالب وتأكد من ظهورها.
7. جرّب الوصول بحساب ثالث غير مرتبط؛ يجب أن يُرفض الوصول إلى بيانات الطالب في Firestore.

## 9) البنية السحابية
```
studentLinks/{studentAuthUID} -> parentUid
families/{parentAuthUID}/students/{studentAuthUID} -> name, track
families/{parentAuthUID}/students/{studentAuthUID}/learning/progress
families/{parentAuthUID}/students/{studentAuthUID}/notes/{noteID}
families/{parentAuthUID}/students/{studentAuthUID}/rewards/{rewardID}
```

## حدود النسخة
- هذه نسخة تجريبية لا تتضمن اختبارات تلقائية لخوادم Firebase الفعلية.
- حساب الطالب يستخدم البريد وكلمة المرور، وليس رمز دخول سريًا بدون حساب.
- مسار إنجليزي الحياة الكامل V4 لم يُنقل بعد بصورة مستقلة إلى V5؛ مسار `life` يستخدم حاليًا دروس التأسيس، ويحتاج محتوى المواقف الحياتية في تطوير لاحق.
- لا يوجد بعد إشعار فوري أو إشعار هاتف عند إضافة رسالة.
- ينبغي تنفيذ قواعد أدق وعمليات مصادقة والتحقق الخادمي قبل تحويل المنصة إلى خدمة عامة.
